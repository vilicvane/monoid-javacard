# Boolean Taproot options — 2026-10-12

The user approved extending Sign/ViewKey to `taproot?: Taproot | boolean`:

- Omitted or `false`: no adjustment, including ECDSA/EdDSA requests.
- `true` or `{}`: BIP86 adjustment without a script-tree root.
- `{merkleRoot: byte[32]}`: the existing script-root adjustment.
- Enabled Taproot requires secp256k1, and signing requires Schnorr.

Only the two command parsers change. They distinguish a CBOR map from a strict
boolean before deciding whether Taproot is enabled. Maps are entered after
outer request fields have been read. Keystore, crypto libraries, transport and
allocation policies are unchanged. Null, strings, arrays, integers and other
non-boolean/non-map values remain invalid. README and the Bitcoin guide reflect
the union type and ECDSA/EdDSA's optional `false` field.

All 91 simulator tests and production/isolated CAP conversion and verification
pass. Tests cover direct/seed/master queries and signing, unchanged chain codes,
false equivalence, incompatible enabled requests, invalid types and fragmented
boolean/object requests. The existing simulator cannot perform ECDSA's
precomputed-digest signing; its known internal-error result is not evidence of
a valid ECDSA signature, so this combination is checked independently on card.

Five targeted physical groups pass with 13 independently verified signatures
(11 Schnorr, one ECDSA and one Ed25519). They cover direct/seed/master boolean
queries and signatures, ECDSA/EdDSA false acceptance, enabled incompatible
requests and invalid CBOR types, fragmented boolean requests, original object
and omitted forms, and physical reset/re-authentication. Idle transient memory
returns to 2192B. This is focused verification of record 80, not a rerun of all
23 record-79 hardware groups or a new performance benchmark.

The tested card/reader and isolated AIDs are the same as record 79. Evidence is
under ignored `.research/taproot/boolean/`: `report.json` includes the 57-file
source manifest, CAP hashes and transcript; production/probe build logs record
CAP verification. Post-test source hashes still match the tested manifest.
Both isolated packages were uninstalled; registry-before/after match exactly;

successfully and releases the reader. Prettier and `git diff --check` pass.
