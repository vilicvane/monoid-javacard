# Identity alias、Hello Bundle policy 与 Authority 互操作

[user] 批准 Identity 持久保存卡别名：UTF-8 字节，最多64B，空串清除；固件只检查长度，不验证或规范化编码。条目 alias 同样按 UTF-8 原样保存。IdentityShareable getter/setter，setter 沿用 Bundle 管理的 Monoid 调用方及 Secret PIN 授权；Monoid 新命令 `0x27 {alias:string} -> {}`，超长为 `INVALID_PARAMETER`。Hello 增加 `alias:string|false`，空别名为 false。

[user] `0xFF Reset` 和 Monoid 替换保留卡别名；重建 Identity 丢失，由 APP 重新设置。不改安装参数，别名不进入 Bundle 状态、入组包或条目导出/导入。Hello 保留 `bundle` 的 SHA-256(root) 含义，平铺增加 `allowPeerExtension:boolean`，未入组为 false。不返回 Authority 公钥；Join 的 Authority 公钥不匹配保持 `6985`。Join 只能幂等接受相同 root/策略，不能覆盖既有 Bundle，也不提供 replace。

[user] Review要求避免每次改名分配新的持久数组：构造时一次分配 final alias[64]，另存持久 short aliasLength，0表示无别名；在同一事务中先写字节、后写长度，getter仅返回有效长度的global副本。

[agent] Identity setter 沿用 assertMonoidCaller/assertCommunicationAvailable/assertSecretAuth，检查长度后按 publishBundle 的 begin/commit/finally-abort 模式更新固定缓冲区；使用参与事务的 Util.arrayCopy，再发布 aliasLength，setter不再分配数组。getter长度为0返回null，否则复制有效前缀。Safe 同样沿用 Bundle 的 Command.requireAuth(AUTH_SECRET)/checkAccess，映射超长请求为业务错误。Reset 原有发布路径不接触 alias/aliasLength。新增 getAllowPeerExtension 只读现有 Bundle 策略，不改入组或加密格式。

[agent] 互操作测试复用现有 JUnit Card/APDU 模拟器与 ProcessBuilder 模式。Node 脚本通过同级 `../monoid/workers/authority` 的 esbuild 依赖在内存打包当前 `src/crypto.ts`，直接调用 `AuthorityCrypto.generateMaterial/create/issueBundle`；无协议重实现，无 dist 副本、网络服务或磁盘密钥。Node 管道先返回公钥供 Identity 安装，再按模拟器卡公钥签发。测试依赖该 checkout 及其 npm dependencies，缺少时失败而不跳过；README 说明前提。Gradle 跟踪脚本、Worker src 与 package-lock 输入，变更会触发测试重跑。

[agent] 覆盖 Worker 哈希与 Join/Hello 一致、两种策略、错误 Authority/目标公钥、冲突 Bundle 拒绝、重复 Join、重启和 Reset；禁用策略拒绝 Extend/Approve。alias 覆盖授权/调用方隔离、64B多字节边界/65B拒绝、原样保存非法UTF-8字节、global副本隔离、清空、重启/替换/Reset、卡别名与条目别名及Bundle隔离。新增测试辅助 applet 曾在空输入上调用 jCardSim Util.arrayFillNonAtomic；字节码确认其先读 buffer[0] 导致6F00，改为只对非空输入翻转首字节验证所有权，未改固件行为。
