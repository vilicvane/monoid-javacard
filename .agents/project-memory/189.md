# Monoid／OTP 共享 APDU 传输

[user] 批准将 Monoid 与 OTP 的 ApduTransport 抽到 monoidlib，并顺便检查遗漏的共用代码和重复分配；遵循现有结构与风格。

[agent] 实现边界：

- `monoidlib.ApduTransport` 接收 reader／writer，统一短 APDU 的 SINGLE/FIRST/MORE/LAST、INS/P1/P2 匹配、GET RESPONSE、错误清理和命令收尾 GC。公开 `clear/clearRequest/isReceiving/process/receive` 为 final；protected 构造及 `supports(byte)`／`execute(byte)` 两个钩子供客户端分派。未知 INS 在接收数据前拒绝。
- 3B header、一个 short 的 state、reader／writer 均是实例字段；共享代码不共享应用状态。Monoid／OTP 仅保留各自命令表的薄适配。外部 APDU、CBOR 与 SIO 签名不变，Security Key 的 CTAP 传输及客户端 token 连接逻辑保持独立，Identity 不依赖公共库。
- OTP Prepare 的 41B data／64B signature 直接由 `bytesGlobal` 读出并传 Identity 验证，去掉先持久复制再转 global 的 105B 中间数据；challenge 仍在调用时复制为 global，跨 SELECT 保留的 time8／indices 仍持久。全部请求字段在 `connect()` 借用 APDU scratch 前已读出。Calculate 的四处 global 分配改用既有 Utils helper。
- 源码审查未发现 monoidlib 反向依赖业务包；未为合并算法或协议而增加统一抽象。
