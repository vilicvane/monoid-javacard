# Production P-256 SIO working-memory adaptation

[user] Approved implementing the lifecycle and crypto-engine adaptations after
record 132's physical probes and clarification of selected-app versus SIO
execution context. Subsequent questions clarified that the existing APP uses
the 0x41 Sign entry point; checking it is regression coverage, not a new user

[agent] Applied the tested changes to the production P-256 / Monoid-001 call

it does not add the unapproved authorization interfaces, grant storage or CTAP
frontend. No APP changes or formal-AID deployment are part of this step.

## Implementation

- MonoidApplet's initialization scratch uses CLEAR_ON_RESET. The initializer
  remains private and no research entry point is copied into production.
- CurveSECP256r1's private key and public-key scratch use RESET, and its ECDH
  engine uses externalAccess=true. KeyBuilder's keyEncryption remains false.
- LibHMACSha512's native HMAC Signature and fallback SHA-512 engine use
  externalAccess=true. HMAC keys, fallback scratch and returned digests use
  RESET. Both native and software HMAC remain supported by feature detection.
- Monoid001Derivation, WeierstrassCurve's allocating public-key overload,
  OneShot.sign and LibECDSA's normalization scratch use RESET.
- Utils gains explicit duplicateAsTransientReset overloads. DerivedKey uses
  these for key and cached public-key working copies; Monoid001Derivation and
  OneShot use the range overload. The existing DESELECT helper keeps its old
  meaning and other callers are not silently migrated.
- Command authentication and transport keep their existing lifecycle. Other
  algorithms' own DESELECT workspaces remain, so this does not claim that
  BIP32, Ed25519 or Taproot can already be called through SIO.

These changes affect shared helpers used by existing algorithms, which is why
regression coverage includes their current APP command paths. RESET arrays
remain transient; the change neither adds persisted workspaces nor changes
the persistent derivation-cache policy.

## Physical verification

The production sources were frozen with 277 hashes in the ignored
`.research/sio-signing-20261019/` harness. Generated copies only remap package
names/AIDs and add temporary probe entry points; the tested working memory and
engine configurations are exactly the production changes. The probe's own
input copies explicitly use the new RESET helper.

Card 55690320 passed 30 main checks for direct/cross-applet seed/master P-256
public keys and signatures, uncached contexts, cache hits, caller rejection and
recovery. Six APP/SIO switching cycles verified 18 signatures and preserved the
existing authentication boundary. Confirmed unpower/reset then passed four
checks: Safe auth starts cleared, cached PIN revalidation restores access,
and public-key derivation/signing remain correct. These suites account for
36 independently verified signatures and nine public-key comparisons.

All six switching-cycle memory queries report RESET 2130B / DESELECT 2128B,
matching record 132's adapted probe. These are query-time readings, not peaks
or independent pools; the saturated persistent reading does not quantify
storage use.

Additional APP command regression passed all 55 requests across two rounds of
eight cases: BIP32/secp256k1, BIP86/BIP340, Monoid-001 seed/master, SLIP-0010
Ed25519, and direct Ed25519/secp256k1/P-256 keys. Each case verifies ViewKey and
two signatures; Ed25519 signs a 300B message using fragmented requests. This
adds 32 independently verified signatures, 16 public-key comparisons and six
chain-code comparisons. All eight Ed25519 signatures also match deterministic
host output; altered-message verification fails for all 32 signatures.

The complete current-production physical run therefore verifies 68 signatures
and 25 public keys. Broad algorithm regression ends with query-time RESET
2034B / DESELECT 2032B after initializing the additional signing contexts.
The result is functional regression evidence, not an old/new performance
comparison or a peak-memory measurement.

Final cleanup removed all five temporary instances and five packages under
E0/E1/E2/E3/E7. Full registry/ownership/privileges/versions/management-key
metadata match the preflight baseline. The original Monoid still returns
SELECT=9000 and its pre-existing Hello=6F00. All card processes exited, and the
277-entry source/probe manifest still matches. Existing applications were not
replaced; formal firmware is built but not deployed. No commit/push was
