# Identity token 直接比较 global 返回值 — 2026-10-20

## 需求与实现

- [user] 要求先修复每次 Identity token 校验都新建持久副本的问题，并测量改善。
- [agent] 本轮仅移除 `Safe.requireIdentity()` 的候选持久副本、`identityCheckToken` 字段及 `identityValidation` 回调；保留三轮完整比较、token 公式、32 槽缓存、PIN 路径和首次持久绑定。不将三次 AID 加入 HMAC 的讨论实现到本轮。
- `identity.getToken()` 返回的 global 数组仅存局部变量，并传给包内 `LibSecurity.check(byte[] expected, byte[] actual, short conservativeResult)`。重载每轮执行原 XOR/OR 比较，沿用 `CHECK_ROUNDS`、`completed`/`remaining` 范围与收尾检查、保守返回编码；原公开 Condition 重载不变。Identity 包中的 LibSecurity 由 Inplate 同步，但未使用新增重载。
- global 引用不得存字段或数组元素，但可以放在局部变量和参数。旧副本是无参数 Condition 通过字段取得数据的需要，三轮比较本身不需要持久化。首次 `initializeIdentity()` 的私有 token 仍作为跨复位、Identity 更换检查的基准，不自动重绑。
- 每次正常检查省掉一个持久 byte[32]、32B 复制以及候选字段赋值/清空；Hello 三次共省96B临时持久内容，不计对象头。Identity 返回的 global32仍分配，因此不是零分配，也不能称作释放32B RAM。
- 原命令 finally 已请求对象删除，旧候选在清字段后可回收；本轮解决重复分配/写入/回收开销，不是修复已证明的永久泄漏。APDU、SIO与公开Java接口均不变。

## 验证与实卡边界

- 327项JUnit零失败/错误/跳过，`check buildJavaCard`、两正式CAP转换/验证、Prettier、Inplate及diff检查通过。新增数组比较测试覆盖两种保守方向、32B每bit差异、多字节差异不抵消、长度/缺绑定及非法保守值。原Identity更换后及复位后拒绝测试继续通过；输入变异不等于物理故障注入。
- 本轮研究目录为忽略的 `.research/identity-token-copy-20261020/`。先冻结含现有token缓存的83个生产源作baseline，再修改候选；源差异严格为Safe和两份LibSecurity。698个输入哈希核对，8个隔离CAP全部converter零错误/警告且验证通过；计时版仅归一命名空间/AID，内存版剥离探针后逐文件还原计时源。
- 实卡CPLC55690320，ACS ACR1552 PICC，PC/SC报告T=1。四组使用预检为空的E0/E2临时包；计时每版108次、内存每版31次，共278/278业务操作通过。每条操作的请求/响应长度和分片数一致；导出与两个host入组包均独立解密，导入Bundle后再导出验证真实根密钥。是一张卡与两个host成员，非三张实卡互刷。
- 最终E0/E2实例和包全部清理，ledger为cleaned，完整registry与测试前一致。原Monoid F06D6F6E6F69640101的SELECT9000/Hello6F00是预存状态，前后保持一致，不称作业务健康检查；读卡器已释放。未改正式应用/数据，未提交或推送。

## 内存与路径

- 两版空闲RESET一致：初始1942B、完整流程后1417B；DESELECT对应1936/1408B。17项操作最低采样值全部一致，最紧为Create Bundle RESET373B/DESELECT368B；正常/幂等入组RESET465B，非对称Import32/256B均550B。
- RESET/DESELECT池重叠，不相加；探针为指定位置的最低采样值，不是连续原生峰值。本轮没有新增transient工作区，global返回数组保留，因此没有测得RAM收益。
- 持久剩余空间值32767已饱和，无法据此量化持久总空间收益。96B/Hello是源码可数的临时数组内容，不是卡上总占用读数。
- 双方首次Hello有HMAC/cache miss与hit；之后所有Identity相关样本只hit，包括reset后。两版均只占首个cache槽，不代表满32槽的耗时。
- 检查点59在基线为私有复制后，候选为global接收后；候选删除原字段清空点61，比较完成点60的位置相应变化。旧checkpoint-map通用文字中“相同采样位置”不能作为逐点等价依据，应读manifest及追加说明。旧统计字符串中的“after one warmup”也不适用于peak/reset：summary明确断言peak无warmup操作且case.warmups为0。
