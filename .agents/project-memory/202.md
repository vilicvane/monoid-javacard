# Bundle 授权分支与 RPC 错误边界（2026-10-28）

[user] 要求修复双向绑定的审查问题，并明确：处于 APDU RPC 范围内的错误应通过 RPC 响应；传输层错误保留状态字。允许完成修复并提交，其他同步可随后处理。

## 实现

- Safe 通过 `Command.requireAuth()` 已有的编码状态及重复验证，显式 switch 匹配 AUTH_ACCESS／AUTH_SECRET，其他值拒绝。Access 传安装 token，Secret 传 null；不再用一次相等比较选择这两条路径，也不清除 Identity 中其他调用方的 Secret 授权。
- Access 无 Bundle，或导入已识别的非对称01封装，返回 CBOR `ACCESS_DENIED`。空密文、未知版本返回 `INVALID_PARAMETER`。Monoid 的预读仅用于选择错误；Identity 仍在实际消费版本时独立执行 Bundle-only 限制，且两种权限下均禁止自导入。
- Import 在首次调用数据源前保留索引、metadata、alias、senderPublicKey 的快照。回归测试发现版本预读曾提前触发数据源回调，现已恢复原有快照顺序。
- Monoid 命令初始化、解析、执行及首个响应窗口生成统一在 RPC 捕获边界内。ISO6A80／6700 转为 `INVALID_PARAMETER`；其他 ISO 转为 `{error:{code:'INTERNAL',exception:'ISOException',reason}}`，reason 保留 Java signed short。响应最终状态9000。其他已有业务错误码保持不变。
- `CBORApduWriter.prepare()` 幂等生成下一窗口，不进入 APDU outgoing 状态。命令在 catch 范围内准备，在范围外发送；空响应与异常对象只负责编码。后续 GET RESPONSE 或真正发送失败不能追加第二份 CBOR 错误，保持原有传输终止规则。
- 首次 Identity／Keystore 初始化从 process 的传输校验之前移入 Command 的 try 内。有效 RPC 缺 Identity 返回 CBOR；非法 CLA／INS／分片不受业务初始化影响。直接 Shareable 调用仍在原位置初始化，继续使用自身异常语义。

## 审查结论与范围

- 不能把所有6982解释为“输入 Secret PIN 重绑”：Identity 被替换导致的正向绑定失效不能由 PIN 修复。通用 ISO 诊断不自动授权降级或提示 PIN。
- 原单比较分支在残留 Secret 授权和局部故障模型下有风险，但已入 Bundle 的 Export 还有独立模式选择，并不会仅因该分支就变成任意接收方非对称导出。记录201中的无降级描述是正常执行语义；不是任意指令跳过或物理故障注入保证。
- 保留持久32B摘要工作区，避免占用紧张 RAM；摘要一次批量输出不等同于32次逐字节持久写。实际重新绑定才分配新的 hash 并发布引用，同一 hash 不重复分配，未改成原地更新。
- 未修改 APP、OTP 独立命令错误协议或 FIDO CTAP。文档同步了 Monoid RPC、存储空间不足、Bundle及Authority错误含义，不引入旧接口兼容分支。
