[agent] Implemented the following complete profile, reviewed against
[RFC 5869](https://www.rfc-editor.org/rfc/rfc5869#section-2) and the P-256
rejection-sampling pattern in
[RFC 9180 section 7.1.3](https://www.rfc-editor.org/rfc/rfc9180#section-7.1.3):

```text
label  = ASCII("Monoid-001")                  // 10 bytes, no terminator
master = HKDF-Extract-SHA512(label, seed)     // 64-byte PRK; seed is 64 bytes
for retry = 0 through 255:
    info = label || 00 || context || I2OSP(retry, 1)
    candidate = HKDF-Expand-SHA512(master, info, 32)
    if 1 <= OS2IP(candidate) < secp256r1.n:
        return candidate
fail
```

Equivalently, a candidate is the first 32 bytes of
HMAC-SHA512(master, label || 00 || context || retry || 01). The retry byte
and HKDF block counter are distinct. No modular reduction or scalar offset
is applied. Exhausting all 256 candidates throws CryptoException.ILLEGAL_USE
through the existing internal-error mapping, without a new error API.

A saved master is the entire 64-byte PRK, not private key plus chain code;
the master entry point performs no second Extract. Existing generic master
storage/index encoding remains unchanged. Its category cannot prove which
scheme produced the material; arbitrary BIP32/SLIP-0010 masters do not gain
Monoid-001 provenance from their length. Seed and its corresponding saved
master yield identical keys for identical context.

The external Key branch is now
{index, type: seed|master, derivation: {type: monoid-001, context: byte[]}}.
Context is opaque, including empty; the scheme fixes P-256 and has no
curve/path override. ViewKey returns a compressed 33-byte publicKey without
chainCode. Sign retains ECDSA digest32 and low-S r||s output. Other ciphers,
Taproot (including false), independent-key derivation and the provisional
monoid-p256-v1 name are rejected. There is no new INS, Safe item type,
caller-selected KDF option or Passkey credential format. Application context
encoding should bind purpose and credential association; index, lookup key,
alias, card identity and signing digest are not implicit KDF inputs.

LibMonoid001 is a static library following existing organization. Keystore
retains seed-to-master generation and source loading; its public-key methods
explicitly distinguish FromSeed/FromMaster. signECDSADigest receives separate
path/context arguments: the command's approved scheme selects one, including
a non-null empty context for Monoid-001. It uses the shared P-256 curve and
existing Signer. The lib reuses LibHMACSha512 and LibMath.compare, allocates
one operation's data/candidate/workspace and retains no new shared state.
No defensive checks of controlled library inputs were introduced.
