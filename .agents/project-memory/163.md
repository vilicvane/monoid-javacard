# Assertion and required-value method names

- [user] `assertXxx` throws on failure and returns `void`; `requireXxx` throws on
  failure and returns the required value.
- [agent] Apply that distinction to project-owned validation helpers. Existing
  value-returning methods such as `requireAuth`, `requireIdentity`, `requireKey`,
  `requireSharedCurve` and `requireChunk` retain their names. Test-case sentences
  and third-party assertion APIs are not guard helpers to rename mechanically.

Renamed nine void declarations and their calls, without changing method bodies:

- Bundle: `requireMember` (both overloads), `requirePublicKeysLength`,
  `requireCanonicalMembers` → corresponding `assert` names.
- CommunicationCipher: `requirePublicKey` → `assertPublicKey`.
- Identity ItemCipher: `requireOtherSender` → `assertOtherSender`.
- CBORReader: `requireRange`, `requireLength` → corresponding `assert` names.
- CurveED25519: `requirePrivateKey` → `assertPrivateKey`, including its
  LibED25519 caller.

Four local test helpers return values and therefore move in the other direction:
`assertPackets`, `assertSuccess`, `assertError`, `assertSignature` → corresponding
`require` names. No APDU, CBOR or Shareable method signature changes.
