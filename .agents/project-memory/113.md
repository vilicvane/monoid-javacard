The lookup baseline for `CommandSign` direct ECDSA parses an encoded map ordered as
`index, type, cipher, digest` with nine lookups: index, type, seed, curve, path,
derivation, cipher, taproot, digest. Five fields are absent and cause complete
map scans. The total is 1+2+4+4+4+4+3+4+4 = 30 candidate-key visits for four
encoded entries. Merely matching the encoder's field order does not eliminate
this cost under the current rewind-before-every-lookup implementation.

Repeated scans primarily re-read keys and CBOR metadata. Skipping byte/text
values advances by encoded length instead of reading their full bodies; skipping
nested maps/arrays does traverse their children. Do not describe each lookup as
copying or hashing an entire Solana Message.

The user's original sequential-consumption goal is valid as an optimization
direction. Compatibility permits reordered fields, including nested derivation
maps; physical tests in 112 verify that behavior. At this initial investigation
stage, no change to the public protocol, parsing semantics, field validation or
production source was authorized or implemented. A forward-reading
implementation must handle optional/absent fields, map bounds, nested snapshots,
and the differing value-reader cursor positions together. Deleting the initial
rewind alone is insufficient. A fixed field order must not become an implicit
new requirement on existing clients.

Record 112 measures complete commands: e.g. cached BIP32 ViewKey is about 705ms,
and direct ECDSA Sign about 634ms after the RAM fix. These include authentication
checks, Safe access and cryptographic work and cannot stand in for Reader timing.
The 361ms reduction in direct Sign is saved overhead, not the remaining parsing
cost.

[agent] Under the user's conditional authorization, production Sign and ViewKey
now use `CBORMap`, returned by the new `CBORReader.map(Object[] keys)` overload.
Each map view traverses its entries once to record known field value offsets in
a transient short array. It retains the first occurrence of a key; later access
positions the existing reader directly at that value. Value decoding remains
conditional on the selected key type, derivation and cipher, preserving ignored
irrelevant fields and avoiding extra copies of Message data. Parent and nested
views are independent, so these two commands no longer need snapshot/restore to
return to the root map. Existing reader methods and their cursor semantics are
unchanged.

This is a once-per-map field index, not a claim that each encoded byte is visited
only once: skipping a nested map while indexing its parent visits nested metadata,
and constructing the nested view visits that metadata again. Values are decoded
later from their recorded offsets. A map view also adds a short-lived object and
transient offsets array, so the eager probe's timings are not measurements of
this production design. Only Sign and ViewKey are integrated; single-field
commands do not gain an unnecessary map index. External command identifiers,
fields, responses and acceptance of arbitrary map key order are unchanged.
The separate production measurement below includes those indexing costs.
