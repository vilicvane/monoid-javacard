# Security Key 性能优化与实卡对照

[user] 要求优化 Security Key，继续检查直至未再发现显著的性能优化点；已放置实体卡并授权独立操作。范围仍为 Java Card，不修改 APP、不改变已批准的 APDU/Shareable API。本轮没有提交或推送授权。

## 已实现的优化

[agent] Security Key CBORReader 游标及共享 CBORWriter 的 offset/initialOffset 改为小型 transient 状态；请求和响应主体仍持久化。CTAP 响应通过 APDU 的 64B 局部窗口批量写入持久 response，不在对象字段保存 APDU/global 引用，发送前提交尾块。Writer 按传输实例复用，GetInfo 复用零 AAGUID。CBORMap 用零表示不存在，避免逐字段初始化 -1。

Credential.encode 直接计算准确长度，移除 1200B staging；DER 编码先求整数长度再一次分配。每次签名操作仅生成一次 78B 派生 context。凭证读取借用局部 APDU 缓冲作为 SIO 窗口，移除额外 64B global 数组和小窗口多次读取；格式、UTF-8、index/key/RP/ID、公钥一致性校验保留。

MonoidSession 的内部 seed 路径在同一授权窗口中直接使用已校验的持久数据，避免重复句柄读取和 64B seed 复制；没有外部 callback 插入。每次 SIO 仍重新验证 seed 类型与长度，派生前后检查授权。SafeSessionItem/Data 使用目录 revision 避免目录未变化时重复线性查表，仍检查调用方、原 grant、Type、secret 和 backing data 身份；目录变化时重查对象身份。GetNextAssertion 保留新的会话和凭证读取，不跨操作缓存授权。

ClientPIN 的 sharedSecret32、workspace64、hmacBlock64、receivedAuth16 和 AES256 key 改为 DESELECT，合计 208B payload 移出 RESET；token、ECDH 私钥、PIN 失败预算仍为 RESET。只调整命令 scratch，不改变跨 Applet 切换的 PIN 会话语义。

## 本地验证

最终保留版本456项JUnit、55个套件全部通过；Identity/Monoid/Security Key三份正式CAP零警告且校验通过，Inplate和格式检查通过。首轮451、索引/输出优化454以及未采用候选461为各自阶段的计数。实际模拟器select-other-select测试覆盖PIN token/ECDH与重试预算保留；CBOR窗口覆盖64/128/133/256/260/1200B、尾块及覆写后的字段独立性；DER测试对照BigInteger验证16,641组整数编码。

jCardSim 的 EC 私有标量从 32B 缩为 31B 后保留尾字节，已在模拟器生成源码中固定为 32B；生产代码不含这一 workaround。模拟器 AES key factory 同步识别 TRANSIENT_DESELECT。模拟器不证明实卡容量、GC、持久回滚或物理抗故障。

## 实卡隔离边界

卡 55690320 的用户试用 E0/E2/E3 安装以及新注册的 F101 WebAuthn 凭证保留。原 Monoid 有两条记录和一项授权。本轮另建独立随机 seed、D301/F102 grant 和测试凭证，仅通过所有权清单操作。删除这些测试对象不清空原 E2 的 32 项派生 FIFO；测试缓存可能留到自然淘汰，不声称存储使用逐字恢复。

完整新旧环境共存受容量限制。完整/ES256 fixture 的 LOAD 返回 6A84；更小的 D0/D2/D3 组合虽可安装，却只剩 142B RESET，初始化 Identity token 复制时 NO_TRANSIENT_SPACE。不能为完成基准删除用户安装或降低 Safe 的 4KiB reserve。

因此分开验证：D3-only 替换 Security Key，继续使用未更新的 E2；core fixture 用独立 D2 和小型 D4 client 比较 Monoid 运行路径，不包含 FIDO 解析或 Identity 管理。core 的一次性初始化直接创建随机 seed/grant；运行时授权、派生、签名和存储方法逐字保持对应源码。不能把两组耗时相加当作完整新版实测。

## D3-only 初步结果与限制

未调整的旧 D3 首次注册 NO_TRANSIENT_SPACE；仅将其 ClientPIN scratch 调到 DESELECT 的控制版仍在 Credential.encode 完成后失败，检查点 RESET 仅剩 7B，尚无 F102 新记录发布。诊断只加持久字段，不新增 RESET 数组；插桩耗时不作为基准。

优化 D3 + 旧 E2 的三个单凭证样本：GetInfo 约161ms，PIN 协商及 token 合计648ms，空库注册2023–2114ms，known-ID 登录1261ms，resident发现及签名1297–1303ms。后续同 RP 第二条注册返回 CTAP OTHER，旧成功 F102、原用户 F101 和其他 metadata/grants 均保留；该完整 bench 未通过，不能以其局部成功宣称四加一账户覆盖。候选诊断确认同样为 NO_TRANSIENT_SPACE，Credential.encode 后 RESET43B；后续存储复制不能分配，旧凭证数据 SHA-256 不变。

## 剩余热点的继续处理

首轮54次阶段计时及64次完整验签显示：旧E2加优化D3的lookup/read/parse阶段，单条known-ID约426ms、resident约470ms。计时来自相邻前缀APDU之差，包含插桩、异常收尾和传输差异，不能作为可精确相加的CPU时间。

MonoidSession在同一会话中复用完整private派生输入，只在总长和context字节相同时命中；grant/domain由会话绑定。每次调用仍重新认证当前caller/grant、读取和校验当前seed、执行加密后检查。没有缓存授权，不保留传入global引用，也不跨会话复用。输入原地修改、空值/长度变化、撤权及seed替换均有测试。

core/candidate3只在candidate2基础上增加该复用；相同payload、计时循环及验签程序，同卡三样本首次派生/公钥/签名741.51→711.64ms，warm414.58→396.91ms。每次APDU仍新建并认证会话。6次独立验签和8项负例通过，D2/D4已卸载，原registry完全恢复。这不是完整FIDO新旧组合的对照，原E2仍未升级。

OneShot.sign在实际输出长度等于新分配数组长度时直接返回该数组，保留变长输出的复制和finally.close。当前ECDSA-PLAIN固定64B路径少分配一个RESET64B数组；数组每次签名独有，不引入别名缓存。core/candidate4以candidate3为父只改变该返回分支；6次实卡独立验签和8项负例通过，首次712.86ms、warm393.86ms，耗时差异很小，不宣称显著加速。主要收益是减少64B临时payload和一次复制。正常卸载完成，原registry恢复。

## 未采用的短凭证直接解析

曾给Security Key Reader增加内部APDU模式，短凭证直接解析局部APDU内容，避免完整persistent原始记录副本；完整字段/schema/UTF-8及metadata绑定校验保留，所有字段在下一次SIO前独立复制。461项测试及CAP通过；实卡candidate-d3-direct-read完整8次注册/30次断言也通过。

但相同常规bench下，known-ID单凭证1210.70→1251.15ms，resident1257.36→1286.16ms，四凭证首响应2453.45→2496.00ms，四签名总5449.04→5568.82ms。GetInfo164.01→166.39ms、PIN614.51→636.39ms也略增。新Reader字段初始化和通用buffer访问的成本可能抵消复制节约，但没有逐项隔离，不能断言精确归因。这一候选没有证明收益，因此完整撤回两处生产改动及独有测试，恢复final-ram冻结点；实验源码及证据留在忽略目录。最终不包含APDU模式Reader。

对多凭证发现的瘦快照也进行了成本审查。四条224B示例每条字段payload约201B，只保留ID/RP hash可少复制字段，但现有逆序返回与resident过滤意味着扫描完才确定首个结果，简单方案需要再完整读取首条。四次断言总计字段复制1407→1060B（少347B及约13个数组），却增加完整读取、解析和SIO；不能据此推断速度提升。保留完整字段所有权及跨APDU重新授权/读取，未引入延迟视图或跨命令会话缓存。
