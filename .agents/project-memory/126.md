## 实现

- Safe内统一`checkStorage(short length)`使用32位`JCSystem.getAvailableMemory(short[], offset, MEMORY_TYPE_PERSISTENT)`，两个short按高位/低位无符号解释。预分配4B CLEAR_ON_RESET数组，避免在低空间检查时分配工作数组，也避免使用已弃用的16位查询。
- 常量`MIN_AVAILABLE_PERSISTENT_MEMORY = 4096`。剩余空间小于`4096 + 预计分配长度`时请求GC并抛出标准`SW_FILE_FULL / 6A84`，等于时通过；不新增请求字段或Shareable方法。
- `createItem`覆盖普通创建、随机密钥及导入新项；只在分配前检查一次，估算index/key/alias/data的总长度，目录扩容时另加完整新引用数组长度（每引用约2B）。旧目录此时仍占空间，不能只计算扩容差值。对象头、数组头、对齐等由4KiB余量吸收，不在写入后复查。
- `setAlias`的非null替换、两种`setData`按新数组长度只在复制前检查一次。guard拒绝保留该次Safe写入的原值及secret。删除、null alias及单独secret变更不触发新空间分配，不受guard阻止。PIN流程保持原样。
- 这是写入准入检查，不是全卡隔离预留区。返回wrapper、响应缓冲和其他Applet仍可能暂时占用余量；替换时尚未回收的旧数据和临时对象会使检查偏保守。
- 现有CommandSet先更新data/secret，再单独更新alias，不是整个请求的事务。本轮不扩展SIO或修改该既有语义；若后一步alias被拒绝，前一步data更新仍可能已成功，文档明确说明。
