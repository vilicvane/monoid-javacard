# Schnorr and Taproot integration — 2026-10-12

The user approved the API in record 78 and requested complete implementation
following the existing Java Card structure. Work is confined to Monoid Java
Card. No APP changes, new command numbers, Safe item types or transport changes
are included.

`LibBIP340.sign` implements tagged hashing, auxiliary nonce derivation, even-Y
normalization and modular Schnorr signing. `LibBIP341.tweakPrivateKey` applies
TapTweak, rejecting a tweak outside the curve order or a resulting zero scalar.
Both are static libraries using the existing shared `CurveSECP256k1` and
`LibMath`; the curve additionally owns a shared SHA-256 engine. They reset the
hash in `finally` and support overlapping output. There is no new generic
point framework, retained signing session or cross-command scratch cache.

`Signer.signSchnorrDigest` generates fresh 32B auxiliary randomness on the card.
`Keystore.signSchnorrDigest` follows the existing seed/master/direct-key flow,
derives BIP32 before applying an optional tweak, and signs a 32B digest. ViewKey
uses overloads of the existing Weierstrass methods. The tweak modifies only the
operation-owned key copy; stored key material and the original derived chain
code remain unchanged. Internally, a null root means no tweak, an empty array
means the no-script-tree tweak, and a 32B array supplies the Merkle root.

Commands parse outer fields before the nested taproot map, so CBOR field order
does not matter. ECDSA/EdDSA reject taproot. Schnorr accepts only secp256k1 and
exactly 32 digest bytes. Hello/SystemInformation add schnorr under the existing
secp256k1 capability. README retains concise API definitions; `doc/bitcoin.md`
describes BIP86 paths, output keys, chain-code semantics, script roots, sighashes
and witness encoding. Transaction construction and hashing remain client work.
Card-side signature self-verification is omitted under the trusted execution
assumption and its additional computational cost; this is explicitly documented.

## RAM failure and correction

The first full integration run passed the 16 existing physical regression
groups and a raw derived Schnorr signature, but seed → five-level BIP32 →
TapTweak → Sign returned 6F00. Instrumentation confined to ignored generated
probe sources established that signing had completed: response allocation
needed 256B with only 144B free, raising SystemException reason 2
(NO_TRANSIENT_SPACE). The failed report is
`.research/taproot/integration/card-current-1791804920126.json` and the exact
pre-fix source/CAPs are retained in `integration/before-memory-fix/`.

Reusing BIP32's 37B input and 64B parent-node arrays through the derivation
fixed normal requests. A second run passed 20 groups and 25 independent Schnorr
checks, but a 799B request containing a 600B ignored padding field, a script
root and five-level derivation still exhausted RAM. The diagnostic confirmed
that this card uses the software HMAC backend; its per-level 128B blocks were
also accumulating. The failed report is
`integration/card-current-1791805570436.json`; its source/CAPs are retained in
`integration/after-bip32-reuse/`.

`LibBIP32` now allocates the HMAC block once per nonempty derivation and passes
it through the existing digest overload, matching `LibSLIP10Ed25519`. Alongside
the input and parent-node reuse, five-level software-HMAC derivation allocates
916B less array payload and 12 fewer arrays. Empty paths still return a copy
without these workspaces. All workspaces are operation-local, overwritten per
level and released through existing cleanup; native contexts remain shared.
This does not depend on GC occurring during execution. The native HMAC branch
ignores the supplied block, as it does for SLIP-0010.

Final instrumented diagnostics complete all four signatures. Available
transient memory immediately after encoding the response is 992B for raw
five-level Schnorr, 800B for BIP86, 208B for the 799B script-root request, and
1488B for direct BIP86. These are observed points, not a general worst-case
memory guarantee. Each subsequent SystemInformation query returns to 2192B.
The corresponding diagnostic transcript and CAPs are in
`.research/taproot/diagnostic/`; earlier instrumented versions are preserved in
`diagnostic-before-bip32-reuse/` and `diagnostic-after-bip32-reuse/`.

## Final validation

All 89 simulator tests pass with zero failures, errors or skips. Production and
isolated CAPs target Java Card 3.0.5, convert with zero errors/warnings, and pass
verification. The new tests cover all eight official BIP340 signing vectors,
seven official BIP341 key-path spending vectors, three BIP86 paths, parity,
input/output overlap, invalid parameters and recovery. Complete API tests cover
seed/master/direct items, chain codes, nested CBOR field order, fragmentation,
authentication and reset. Node/noble independently verifies Schnorr results.

The final full physical run passes all 23 groups, with 81 independently checked
signatures: 41 Schnorr and 40 ECDSA/Ed25519. It covers raw and tweaked BIP340,
BIP86 seed/master derivation, script-root commitments, all seven BIP341 wallet
vectors, random auxiliary data, invalid request recovery, fragmented Schnorr
with padding, abandoned request/response recovery, three-algorithm switching,
and physical reset with mandatory re-authentication. Existing regression groups
also cover exact 8192B Ed25519 requests in both field orders, 8193B rejection,
600B responses and full-capacity Safe removal.
