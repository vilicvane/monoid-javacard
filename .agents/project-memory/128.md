# Safe Item 分块读写

[user] 希望处理单个 Safe Item 的 data 过大时操作耗尽 RAM 的问题。内部按块读写与调用方拆成多项都可以，能不拆条目实现需求更好。

[agent] 保留一个 Index 和一个持久 byte[] 即可按偏移复制数据；没有必要为节省 RAM 将持久数组本身拆成 byte[][]。当前限制来自 CBOR 解析和跨 Applet 的完整临时数组。List 已经只读取元数据，不需要加载 data。

## 已批准的 SIO 方案

[user] 明确批准以下 Safe SIO 调整；APDU 和 APP 调用保持原样。

```java
public interface SafeDataShareable extends Shareable {
  short getLength();

  void read(short dataOffset, byte[] buffer, short offset, short length);
}
```

- getLength 在当前操作期间固定，read 精确复制指定范围并允许重读；数据源在当前操作期间保持稳定。调用方提供的 global/APDU 缓冲只在调用内使用，不持有其引用，也不返回 Safe 私有数组。
- SafeShareable.create 和 importItem 的 data 参数由 byte[] 改为 SafeDataShareable。
- SafeItemShareable.getData 和 exportData 的返回值由 byte[] 改为 SafeDataShareable。
- SafeItemShareable.setData 的两个重载将 data 参数由 byte[] 改为 SafeDataShareable。
- 其他参数、权限、APDU 编号和 CBOR 结构保持原有约定。
- 小型密钥在 Monoid 内部按需要读取为完整数组，供现有派生和签名使用；数据源不承担密码算法职责。

## 实现约束

- 输入由 Monoid 在当前完整请求的 ByteSource 上提供数据源，Safe 用有限大小的缓冲读取；新增反向 SIO 调用需要实卡核对防火墙行为，模拟器通过不能替代该验证。
- Create/Set 先填写私有的新持久数组，完成后发布或事务性替换引用；data 与 secret 同步更新。Set 的 alias 仍沿用原有单独更新语义。
- Import 必须验证完整认证标签后才能发布条目；保留重复导入幂等及冲突检查。Export/Import 必须同时消除完整 global 数据副本，单改 Get 不足以完成目标。
- 数据源支持按偏移重读，因此不能把仅支持顺序生成的 GCM 输出直接伪装成该接口。首选沿用现有完整 GCM 运算：大数据的密文和私有解密工作区放在临时持久数组中，跨 SIO 仅复制小块。这会占用额外临时持久空间；不把降低 RAM 占用描述为不需要额外空间。
- Safe 返回的数据源沿用会话与调用方授权检查，不暴露私有持久数组。未完成响应的释放接入现有 writer 生命周期。
- SIO 签名变化需要 Safe 与 Monoid 配套更新；不改动卡上既有应用或数据，部署另行取得授权。
- 外部仍传递一条完整逻辑请求/响应，不增加分步业务命令，不扩大现有 8192B 完整请求上限。
- 保留写入前的持久空间估算及 4KiB guard；大数据仍需相应的持久空间，不能将分块复制理解为无限容量。

## 实现

[agent] 已接入上述 SIO、Reader 数据源和 Get/Export 流式响应；普通数据仍为一个持久数组。Create/Set 使用至多256B global复制缓冲；Import复用113B global缓冲，直接将密文内容读入私有工作区再原地解密，避免额外完整密文副本。小于等于512B的私有加密工作区先尝试transient，较大工作区直接使用临时持久空间。

完整小响应仍借用APDU缓冲；只有超过单包的响应启用固定窗口。输入数据源不保留global/APDU数组，单包输入仍通过Reader访问，复制缓冲独立，因而可重读。

源回调发生前先保存元数据，返回后重新检查授权；数据和secret在完整复制成功后才提交。Create发布前再次核对重复Index和当前目录扩容所需空间，避免回调重入创建同一Index或填满目录时重复发布或绕过扩容前检查。新增模拟器SIO参数包装覆盖反向回调的上下文，但模拟器不模拟真实防火墙和GC。

小型签名密钥按需物化，保留原有密码算法调用。摘要Index对超过256B的数据改用普通MessageDigest逐块计算；OneShot只用于单块，不能使用其不支持的update方法。

### 版本零的重复初始化缺陷

首轮0/32/256/1025/4097B读写及加密往返通过，6145B Create却返回INTERNAL。保持Safe/Identity及生产逻辑不变，只为隔离Monoid增加异常/阶段诊断，确认SystemException.NO_TRANSIENT_SPACE发生在Safe首次read回调之前：调用Monoid.safe.create前剩158B，Safe调用数据源getLength时剩123B。错误后未发布条目。相同6145B请求改用255B分片后可创建并完整读回，排除单个持久数组的长度限制。

原因是MonoidApplet将合法版本0同时作为尚未初始化的标志。当前正式及临时AID末两字节均为0000，ensureInitialization每个APDU都重新分配16B transient AID缓冲；127B分片的49个请求累计784B，255B分片的25个请求只累计400B。完成请求前未回收的差额384B足以解释256B复制缓冲为何失败。

修复使用独立的versionInitialized标志，安装时清除、成功读取AID后设置；保持完整16bit版本值语义。没有采用给每个输入分片追加GC的替代方案。诊断副本和失败日志留在ignored .research/safe-data-20261018，未混入生产源码。
