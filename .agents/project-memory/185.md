# Access PIN 管理 Security Key 授权，FIDO PIN 独立

[user] 明确 FIDO PIN 保持独立；“使用 Access PIN”指用户在 APP 管理 Security Key 的 key/seed 授权，无需输入 Secret PIN。

[agent] 此前把需求理解为 FIDO PIN 与 Access PIN 共用属于误读，相关共享方案从未修改实现，不是待实现事项。Record184 的凭证 scope/标签改动继续保留。

## 实现

- 现有通用 `0x50 List / 0x51 Set / 0x52 Remove Applet Grant` 统一接受 Access 或 Secret PIN，不增加 FIDO AID 特例，不修改字段或 Shareable 方法。
- `AppletGrants.assertManagement()` 复用 `Safe.checkAccess()`：检查 Monoid 命令授权，并确认 Identity Secret PIN 已设置且未锁定，无需验证 Secret PIN。Set 命令移除紧邻的重复检查，保留获取客户端 Shareable 和 token hash 后的管理权限复核。
- 保留安装 token、实际调用方、当前 grant、Type、secret 数据及 seed/domain 边界；授权替换/撤销仍使旧 session 失效。
- FIDO PIN、失败计数、pinToken、系统设置/修改及局部 Reset 仍由 Security Key 独立管理。导出/导入、Bundle 和 Monoid PIN 修改仍需 Secret PIN。
- Access 持有者可委托另一客户端使用相同 seed/domain，获得同样签名能力；FIDO PIN 保护标准 FIDO 入口，不是对 Monoid 其他已授权签名入口的全局第二因素。私钥不因此导出。该边界已写入安全文档。

## 验证

- 更新授权测试，覆盖未认证拒绝、Access/Secret 都可管理、Access 设置各类权限、客户端回调清除授权后拒绝发布、Secret PIN 锁定时禁止管理。
- 真实组合模拟器的 Security Key fixture 改为复位后仅使用 Access PIN 建立/撤销授权，继续验证注册、断言、FIDO PIN、Reset 与 seed/domain 切换。
- 611 项 Java 测试、69 套件、四个 CAP 构建/验证及 Prettier、Inplate、diff 检查通过。包含本轮更新的授权用例和完整 Security Key 模拟器流程。尚未部署实卡或修改 APP。
