The line break above is purely formatting; Q consists of04 followed by64
coordinate bytes. The raw public Q retained in the reproduction is:

```text
0431176cfcaf634cd42e14ef6898d7db730b6035fae26babc94172eaa8d5f95febbdb447f59525157b3e8d5865a46bab6018e1c8563a533fe7c65071055189f6e1
```

The replay validates this public point using OpenSSL before sending exactly the
same logical commands. An independent BigInt check confirms both coordinates
are in range and satisfy the P-256 curve equation. Comparison with record93
shows an identical first command and identical second-command framing; only
the64 coordinate bytes differ. Randomization replaces only DGI0036/Q. The
planned DGI0033/G remains the standard P-256 generator, not the random Q.
The subsequent curve CRT and P/A/B/G/N/cofactor commands were never sent.

[GP2.3](https://globalplatform.org/wp-content/uploads/2018/03/GPC_Specification_v2.3.pdf)
section11.11.4.2.2.2 prescribes Q before its own curve parameters. Q=G is also
a valid public key; there is no standards basis to reject the earlier scalar1
fixture. Thus neither the request ordering nor changing the public point alone
establishes a client encoding bug. The exact repetition strongly associates
this failure with the Q import path, but does not identify whether GP firmware,
reader interaction, or another implementation condition causes the loss.
Do not claim that P-256 hardware support is absent, or that the card returned
6A80 in these two interrupted runs.

The remaining named-reference comparison in the actual ISD TokenVerifier and
a single-APDU STORE DATA reference control were not executed after the repeated
failure. A prepared ISD STORE branch's usage was corrected offline to81
(Token);82 is PK_SD_AUT. It was never transmitted. Do not count prepared
commands or unused script branches as hardware coverage.
