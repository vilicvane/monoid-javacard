# Security Key 无记录非驻留凭证

[user] 要求接受没有记录的非驻留凭证请求，并在认为更好时不再为非驻留凭证保存记录。随后指出不考虑向后兼容：现有密钥都只用于测试。

[user] 要求重构 MakeCredential / GetAssertion 的命令实现。

## 设计

[agent] 非驻留注册不写 F101 记录，Credential ID 自认证：

```text
idKey        = SHA256("monoid fido2 id: " || scopePoint)
credentialId = nonce[16] || HMAC-SHA256(idKey, SHA256(rpId) || nonce)[0:16]
```

- `scopePoint` 是 scope 派生的 65B 公钥，只有其哈希作为 scope 保存，因此不能由存储的 scope 推出 idKey。selectScope 复用已有的一次派生，不增加 EC 运算。
- allowList / excludeList 先校验标签，通过则直接按 `rpHash || credentialId` 派生签名，无需查找或公钥复核；否则按驻留记录查找。不校验标签会让卡片认领其他认证器的凭证，也会失去 seed/domain 切换隔离。
- 签名密钥派生 context 不变；scope 或 RP 不同则标签失败，返回 NO_CREDENTIALS。
- 驻留注册、发现、替换与 GetNextAssertion 行为不变。

[agent] 由于不考虑兼容，记录格式删除字段 8（resident 标志），所有 F101 记录均为驻留；CredentialStore 去掉发现/替换中的 resident 过滤和最后一项重新查找。版本号仍为 1。旧格式中字段 8 被当作未知字段跳过，旧非驻留记录会作为驻留记录被发现。

## 资源

[agent] 新增 32B CLEAR_ON_DESELECT idKey，需跨 selectScope 到所有 allow/exclude 条目保留；中间 find 会覆盖整个 APDU buffer，放持久区则把 seed 派生材料留在 Monoid 外。HMAC 64B pad 与 32B 输出使用 APDU buffer（请求保存在 reader 自有缓冲区，此时 APDU buffer 为空闲 scratch），未增加其他 RAM。最后 64B 残留 `idKey ^ opad`，与原 DESELECT 数组暴露时长相当，未清零。

## 已知取舍

- [agent] CTAP Reset 只删除 F101 记录并清 FIDO PIN，非驻留凭证由 seed/domain 派生，Reset 后仍有效，与 CTAP2.0 “invalidating all generated credentials” 不符。让 Reset 撤销需要加入可备份的 epoch，否则会失去仅凭 seed 恢复的能力。待用户决定，当前保持不撤销并写入文档。
- 非驻留凭证不能用 Monoid `0x35 Remove` 单独删除，只能通过改变授权 seed 内容或 domain 失效。恢复只需 seed 与 domain。

## 重构

[agent] Authenticator 统一 descriptor 解析（readDescriptor）和归属判断（owns），authData 拆为断言 `authData(rpHash, ...)` 与注册 `attestedAuthData(credential, ...)`；sign 增加按 ID/RP 派生的重载。GetAssertion 拆为 readRequest / respondAllowed / respondDiscovered / respondStateless / respond / write，pending 只保留驻留 Selection，直接使用 rpHash/clientDataHash 字段。MakeCredential 拆出 assertNotExcluded 与 createCredential。
