# Chunked request and signing — 2026-10-12

Implements the user-approved decision in record 64, within Monoid Java Card only.
External request/response schemas and CLA 00/90/B0/A0 remain unchanged.

- `CBORApduReader` appends into fixed 256B transient arrays, referenced by a
  fixed transient Object[32]. APDU frame boundaries do not determine allocation
  boundaries. Previous chunks are never copied during growth. Whole single
  frames borrow the APDU buffer dynamically without storing a global reference.
- `ByteSource` exposes the array, physical offset and contiguous available
  length for a logical byte position. `CBORReader` implements it; parsing checks
  ranges and reads across blocks. `getOffset` now returns a logical offset.
- CommandSign, Keystore and Signer pass this source plus the Message range.
  LibED25519 walks that unchanged range twice using SHA-512 update/doFinal.
  Pure Ed25519 semantics remain unchanged; this is not Ed25519ph. Empty messages
  do not access the source. Output is published after both traversals.
- Completion, errors and replacement erase all chunk bytes and release every
  reference. A replacement explicitly requests GC so old chunks can be reclaimed
  before the next frame; GC still is not synchronous. Shared crypto contexts and
  existing response writer capacity/lifecycle are unchanged.

Validation: all 60 simulator tests and both Java Card 3.0.5 CAPs passed. New tests
cover RFC empty/2B/1023B messages through 127/128/129/256B blocks with nonzero
logical and physical offsets, cross-block CBOR keys/length headers/copied fields,
1167B requests in 1B frames, the 8192B ceiling with 17B frames, and full erasure.
