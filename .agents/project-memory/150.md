# Identity 按调用方 AID 缓存 token — 2026-10-20

## 需求与实现

- [user] 确认同一 Applet 的 token 固定，并要求考虑在 Identity 按 AID 缓存，避免每次重算。
- [agent] `MonoidIdentityApplet` 增加实例私有、持久化的 32 槽 FIFO 缓存，沿用现有派生缓存的组织方式；每项只保存自有 caller16、实际 AID 长度及 token32，不保存外部 AID、SIO 或 global 引用。
- token 仍为 `HMAC-SHA256(identitySecret, "Monoid Identity Token" || fullCallerAID)`；同一 Identity 与完整 AID 的结果不变，换 Identity 后变化。缓存淘汰或调用方同 AID 重建后重算得到相同结果，不依赖 Applet 对象身份。
- 每次仍执行 caller admission 与通信重入检查；命中用 `LibSecurity.check` 对运行时完整 AID 做三轮核对，只返回 global 副本，不写缓存。Monoid 的私有绑定、候选副本和本地三轮比较保持不变。
- 未命中先完成私有 entry，再事务发布槽及 FIFO 游标；已有调用方事务时只计算并返回，跳过缓存发布，不提交/回滚调用方事务。复位保留缓存。
- 最多 1536B 是可达 caller/token 数组的内容总和，不含对象头、引用表、entry 与游标；被淘汰对象在 GC 前仍可能占空间。缓存命中仍产生 global32 返回值，SHA 引擎与64B RESET工作区保持，因此不能据此声称回收了记录149的固定179B RAM。
- 最多32槽线性查询；本次真实 Monoid 流程先占槽0，不代表32个活跃调用方下相同耗时。不新增 APDU/SIO/协议变更，不改 APP，不提交或正式部署。

## 验证与证据

- 新增多调用方交替、完整AID长度/前缀、40调用方淘汰重算、相同AID重建、调用方事务abort的5项回归。325项JUnit零失败/错误/跳过，`check buildJavaCard`通过，两个正式CAP验证通过。模拟器不等于物理防火墙/断电原子性验证。
- 实卡实验在忽略目录 `.research/identity-token-cache-20261020/`；基线来自记录149未缓存candidate源快照，候选为当前缓存实现，两版唯一生产源码差异是 `MonoidIdentityApplet.java`。双方使用相同临时AID和调用方域，不再与记录149的旧提交或check-bypass混用。
- 计时版无内存插桩；内存版剥离探针后逐字还原计时版。695输入冻结，8个隔离CAP通过编译/转换/verify。
- 卡为CPLC55690320、ACS ACR1552 PICC、T=1，使用预检为空的E0/E2包。原Monoid `F06D6F6E6F69640101` 在测试前已经SELECT9000/Hello6F00；不能将该旧响应称为健康检查。
- 两组计时各108次、两组内存各31次，共278/278命令通过；所有请求/响应长度、分片数逐项一致。每个导出、入组包用独立host密码学验证，入组后再导出校验真实Bundle根密钥。仅一张实卡与两个host成员，不是三张实卡互刷。
- 最终所有E0/E2实例及包已删除，ledger为cleaned，原完整registry及SELECT/Hello响应与测试前相同，读卡器连接已释放。

## 内存与路径确认

- 两版空闲RESET相同：初始1942B、完整流程后1417B；对应DESELECT1936/1408B。所有17项采样最低值也完全一致。RESET与DESELECT为重叠池，不可相加；不是连续原生峰值。
- 最低可用RESET：首次Hello1745B，热Hello1777B，有Bundle Hello1220B；非对称Import32/256B均550B，Export32/256B为1070/558B；Create Bundle373B，正常/幂等Import Bundle465B；Bundle Import32/256B为1189/677B，Export为1195/683B。最低DESELECT为Create Bundle368B。
- 新缓存只增加持久对象，没有新增显式transient工作区；原SHA引擎和64B工作区仍在，每次返回global32也仍在。`SystemInformation`的持久剩余值32767已饱和，不能拿它量化缓存实际持久总开销。
- 峰值版首次Hello同时出现HMAC完成点55、cacheHit57、cacheMissStored58；之后15项Identity相关样本均有57、没有55/58，包括reset Hello。证明这些路径实际跳过HMAC；System Information不经过token。
- PC/SC reset不是物理断电验证；事务发布的断电安全为源码/Java Card事务语义论证，本轮没有故障注入。实卡只占用第一个cache槽，多调用方隔离/40项淘汰/同AID重建/事务abort由模拟器覆盖，不宣称满缓存实卡性能。
- 原peak console/assertions继承了“after one warmup”的错误描述；操作记录和case元数据实际为零预热，汇总脚本对此做断言。保留原始日志，禁止把旧文字当作执行证据。
