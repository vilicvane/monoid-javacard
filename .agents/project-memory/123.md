# List 条目 getter 的实卡 GC 对照

## 需求与范围

[user] 希望先验证不复用条目读取缓冲时的垃圾回收行为；如果 GC 足以支持，应优先保留原来的可读 getter 用法。

[agent] 基于记录122的未提交实现进行隔离对照，保持相同 Safe iterator、512B RAM 前缀和持久响应 writer，只改变 metadata 读取方式。没有修改正式 Java 源码、手机协议或暂存区。

## 实验

- 卡片 CPLC 序列号55690320，ACS ACR1552，T=1。安装独立 Identity/Safe/Monoid 包 A8/A9/AA，正式及原有应用不动。
- 每条 index10B、key16B、alias9B、data1B；List 不读取 data。先生成完整响应，再按256B GET RESPONSE发送。
- 五种模式：0为现有复用缓冲；1为无参 getter，每条结束清空局部引用；2在1基础上逐条请求GC；3把单条编码放入helper，返回并清空item引用后请求GC；4为helper但不请求GC。
- 使用预分配的12-short transient诊断数组记录完成条数、失败阶段、SystemException原因及RESET/DESELECT可用内存。没有逐次分配统计数组。每次完整读取后再用独立诊断命令取得记录。
- 五种模式各通过5项隔离模拟器测试，共25项；三个隔离CAP转换及验证通过。模拟器仅校验逻辑与编码，不用于判断GC。
- 冻结的生产来源、生成源码及控制命令均有SHA-256校验。临时工具、CAP和原始日志位于已忽略的`.research/list-gc-20261018/`。

## 已观察结果

每次List开始时，RESET/DESELECT可用内存均为2112B。

| 条目数 | 复用缓冲最低RESET/DESELECT | 无参getter最低RESET/DESELECT | 无参getter结果                 |
| ------ | -------------------------- | ---------------------------- | ------------------------------ |
| 10     | 1557/1552B                 | 1242/1232B                   | 成功                           |
| 40     | 1557/1552B                 | 192/192B                     | 成功                           |
| 80     | 1557/1552B                 | 7/0B                         | 完成45条，第46条getKey分配失败 |
| 120    | 1557/1552B                 | 7/0B                         | 完成45条，第46条getKey分配失败 |

- 四种不复用模式在80条和120条测试中均于同一位置抛出`SystemException.NO_TRANSIENT_SPACE`，reason=2；正常错误处理返回`INTERNAL`，卡片保持可用。
- 40条不复用时，RESET读数符合`2112 - 512 - 8 - 40×35 = 192B`。这是本次探针报告的可用空间，不额外推断底层对象头开销。
- 每次失败后，用相同模式查询8条的小前缀列表成功。完整响应及清理后，诊断读数恢复2112/2112B。
- 成功的List逐字段核对index/key/alias/secret；相同列表的五种模式编码hash一致。
- 复用版本返回120条的完整响应为7569B、30个响应包。20次主体List对照和8次失败后小列表恢复共28次；不是每条单独发送。

## 结论与解释边界

- 此卡确实可以回收，但本次List执行内无法及时回收无参getter产生的global数组，甚至在分配耗尽时也没有因此继续完成。逐条请求GC和退出helper再请求GC均不能解决。
- 因此保留记录122的复用缓冲。用户偏好的更可读用法成立的前提，在本卡上没有得到满足。
- 45条是本次带诊断状态、固定元数据和上下文的完成数，不是正式固件的固定上限；其他上下文与字段长度会改变失败位置。关键是RAM随条数线性增长。
- 2112B恢复读数取于完整GET RESPONSE结束后，且诊断命令也执行普通writer.reset，不能据此精确断言首个响应APDU结束时的回收顺序。
- 采样点没有净RAM回升不等于证明运行时内部从未尝试GC；最终的分配失败才是无法依靠它完成长列表的直接证据。
- 原始日志保留命令耗时，但探针包含逐条诊断，且不同模式采样次数不同，不作为未插桩正式版本的性能结论。未进行新的极限容量扩展。
