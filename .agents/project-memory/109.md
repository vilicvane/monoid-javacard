# Custom derivation specification naming — 2026-10-16

[user] After the existing Key API implementation was tested and committed,
requested settling the custom derivation algorithm. Asked whether its name
should describe its purpose or use a protocol/specification number, noting
that version numbers often imply semantic continuity between versions.

[agent] Recommended an independent specification number plus a descriptive
title. Candidate: Monoid Derivation 001, with API identifier monoid-001 and
title describing deterministic P-256 key derivation from seed/master and
context. The number identifies a complete, fixed derivation scheme, not an
upgrade level. A later numbered scheme may coexist without replacing or
preserving the semantics of this one. Specification is more precise than
interactive protocol for this deterministic computation.

The purpose should not be fixed to Passkey: the agreed context-based
primitive can serve other applications. Application-specific context
encoding should distinguish purposes. P-256 remains the fixed output
curve of this candidate specification even if absent from its identifier.

The specification must fix seed-to-master processing, master representation,
context interpretation/encoding, domain separation, hash/PRF and scalar
generation. Changing the meaning or prescribed output for existing valid
inputs requires a new scheme identifier. Implementation optimization,
documentation clarification and fixes restoring conformance do not.
Document revisions are separate from the derivation scheme identifier.

This is a naming recommendation, not user approval. README still uses the
provisional monoid-p256-v1 name; neither the API nor implementation changed.
The exact derivation algorithm and test vectors remain to be agreed.

[user] Objected to the proposed specification name Monoid Derivation 001:
its 001 would be associated with the 001 in the API identifier monoid-001.

[agent] Revised the recommendation to separate the specification identifier
from its descriptive title: Monoid-001 identifies an entry in the general
Monoid specification series; its title describes context-based P-256 key
derivation. The API identifier monoid-001 refers to that same specification.
There is no separate derivation-specific numbering sequence. Other Monoid
specifications need not describe derivation. This remains a proposal;
README and the API have not been renamed.

[user] Approved this naming and requested implementing the previously
discussed derivation using a standard KDF with rejection sampling. Record
110 defines the resulting Monoid-001 profile and implementation.
