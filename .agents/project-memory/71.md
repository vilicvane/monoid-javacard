# On-demand persistent request overflow — 2026-10-12

Implemented on top of `ecae74d`, which committed the response-buffer release fix.
Production changes are confined to CBORApduReader:

- Complete single short APDUs still borrow the APDU buffer.
- Assembled requests use two transient 256B chunks first. Beyond 512B of the
  complete CBOR request, subsequent 256B chunks are ordinary persistent arrays,
  allocated only as received. The RAM prefix is not moved or copied.
- Object[32] is persistent so reset cannot lose references to unfinished data.
  References are assigned before copying payload. Existing completion, error,
  replacement, selection and deselection cleanup erases full arrays and nulls
  references, including unused tails. Reset recovery does not rely on transient
  receive state surviving. Deletion remains asynchronous.
- The 8192B complete-request ceiling and public API/framing are unchanged.
  ByteSource and Ed25519's two complete Message reads need no changes. No
  EncryptedBuffer, full-size payload preallocation or deferred execution is added.
