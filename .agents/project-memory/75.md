# Trusted execution environment and cleanup — 2026-10-12

The user explicitly states that the execution environment is trusted and asks
to remove defensive erasure of fetched key copies and similar usages. This
supersedes earlier requirements to overwrite operation secrets and abandoned
transport data merely to reduce their residual lifetime.

Implementation:

- Keystore no longer wipes temporary key/master copies; try/finally wrappers
  serving only that purpose are removed. Safe.getData still returns a copy.
- SLIP-0010, Ed25519, HMAC and LibMath no longer erase temporary or shared scratch
  after use. Native HMAC and curve multiplication keys are overwritten through
  setKey/setS and initialized for each operation instead of being cleared after
  use. Shared workspaces overwrite the ranges they consume.
- ED25519Key.clear retains its validity-state transition, without overwriting
  scalar/prefix/publicKey. Keystore still invalidates imported keys in finally.
  Hash resets, failed-import handling and curve reference release remain.
- APDU readers/writers release cancelled or completed buffers without wiping
  their bytes. State reset, pending-response handling, reference release and GC
  requests remain. The persistent chunk reference table still releases chunks
  after reset/SELECT. Buffer expansion no longer wipes its old buffer.
- Mathematical padding, zero-valued output construction and HMAC pad
  initialization remain: these determine results, rather than erase secrets.
- Authentication, input validation, request limits and protocol behavior remain.

Validation: all 72 simulator tests pass. Tests retain exact cryptographic results,
shared-resource reuse, invalidated-key rejection, failure/retry, reset/reimport,
fragmented transfer, cancellation and buffer-release checks; byte-erasure
assertions are removed. Both production CAPs pass Java Card 3.0.5 conversion and
verification with zero converter errors/warnings. No physical card was used for
this change; prior numbered records retain their historical hardware evidence.

Subsequent record [76](./76.md) completes physical-card acceptance and a same-card
performance comparison. Current code passes all 16 physical groups and 32
independent signature checks; after the Safe removal-boundary fix, all 74
simulator tests pass. Short Ed25519 signing is slightly slower, BTC is essentially
unchanged, and the tested largest requests are slightly faster. Idle transient
availability recovers to 2320B; both isolated packages uninstall successfully.
