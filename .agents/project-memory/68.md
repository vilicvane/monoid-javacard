# Response buffer release — 2026-10-12

The user identified retained response capacity as a lifecycle bug and requested
its repair. Production changes are confined to the two writer classes:

- CBORBufferWriter allocates on its first write and handles empty copy/get calls.
- CBORApduWriter.reset erases the buffer, drops its reference and requests GC.
- send retains storage for 61xx continuation only; a finally releases storage
  after the final 9000 or an exception. Existing Command cancellation and
  MonoidApplet selection/deselection paths already invoke reset.
- The writer object stays shared. No eager replacement allocation is needed at
  response completion; the next operation allocates when writing its response.
- Object deletion remains asynchronous. This does not guarantee synchronous
  reclamation inside a command that cancels an earlier pending response.
