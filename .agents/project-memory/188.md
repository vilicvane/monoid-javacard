# Card ID 生命周期与 Identity 安装配置

[user] 要求 `0xFF Reset` 保留 Card ID，安装时可以同时提供 Card ID 以便重装恢复；批准紧凑安装格式：1B flags，bit0 表示 4B ID，bit1 表示 65B Authority 公钥，字段顺序固定；空参数随机生成 ID 且不配置 Authority。

[agent] 已实现上述安装参数和 Reset 行为，保持 Identity 独立 CAP。Authority 的单密钥方向及后续证书设计见 187；本轮没有新增可信时间/卡证书验签或复制权限。

## 格式与生命周期

应用数据位于标准 GP 安装缓冲的实例 AID 和控制信息之后；此处不重复 GP 外层包装：

```text
empty                   -> random ID, no Authority
00                      -> random ID, no Authority
01 || id4               -> supplied ID, no Authority
02 || authority65       -> random ID, supplied Authority
03 || id4 || authority65 -> both supplied
```

- Authority 公钥使用未压缩 P-256 点 `04 || X || Y`，导入持久 ECPublicKey；不缓存安装缓冲引用。无配置时不分配该公钥对象。
- 未知 flags、错误字段长度和非 `04` 公钥前缀拒绝安装。安装数据最多 70B，不使用 CBOR，也不新增公共 CAP 依赖。
- Card ID 字段改为 final；ResetState 不再创建随机 ID，Reset 不再替换 ID。Authority 公钥也属于安装配置，Reset 保留。
- Reset 仍更换卡自身 P-256 密钥、私有绑定 secret/token、清除 token 缓存、PIN、Bundle、Monoid 数据和授权。短 ID 不用于安全认证，不能以恢复 ID 来恢复旧密钥、绑定或证书资格。
- 重装 Identity 时可重新提供同一 Card ID，但仍生成新的卡密钥和 token。其他调用方保留的旧 token 不会因 ID 相同而重新有效。
- `scripts/build-install.ps1 -Mode Install` 增加可选 `-CardId`（8 hex）和 `-AuthorityPublicKey`（130 hex，04 开头）；仅发送至 Identity 安装。`ReinstallMonoid` 拒绝带这两个参数，避免看似设置却忽略。
- 没有新增 Authority 运行时 setter/getter 或管理 APDU；当前只完成安装配置，具体验签业务另行设计。

## 验证

- 65 项模拟器测试、4 套件通过：Identity、Bundle、Applet grants、Item transfer。
- 新增 5 项安装测试覆盖所有参数组合、标准三段 LV、非零输入 offset、非空控制信息、自定义实例 AID、入参缓冲复用、Reset 保留配置但轮换私钥身份，以及非法配置拒绝。更新既有 Reset 断言，继续验证旧密文和 token 失效。
- jCardSim 默认 installApplet 重载传空数组，五参重载原样传递缓冲；新增测试显式构造 GP 包装，不能将原始应用数据直接当 install buffer。生产接受空 length 维持默认无参数路径。
- 模拟器不支持四参数密钥工厂，按既有 gradle/simulator.gradle 方式在生成副本替换；生产使用 3.0.5 四参数 API。
- 四个 CAP 均编译、转换和校验通过；目标格式、Inplate、PowerShell 语法和 diff 检查通过。
- 未操作实卡、未部署、未提交推送。模拟器测试不证明实卡安装、事务回滚或新公钥对象的实际内存开销。
