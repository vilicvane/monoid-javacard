# List 逐项枚举与响应持久化

## 已批准方向

- 用户要求返回数量不受 RAM 容量限制，假设单条元数据不大，仍由传输层打包并分包发送。
- 讨论过按 GET RESPONSE 逐步生成，但最终批准的是 writer 按需持久化、Safe 逐项枚举、复用条目读取缓冲。保留一次命令执行内生成完整响应，随后发送的结构。
- 此批准覆盖所需 Safe SIO 枚举与缓冲读取接口；手机 List 请求、响应字段、顺序和 GET RESPONSE 协议不变。

## 实现

- `CBORApduWriter` 小响应继续借用当前 APDU。拥有的前两个 256B chunk 使用 `CLEAR_ON_DESELECT`，后续 chunk 使用持久 byte 数组；增长不搬动旧块。分配入口在 base 的 `createChunk`，普通 `CBORBufferWriter` 仍全部 transient。
- 沿用记录121的清理：响应结束、取消、deselect、reset 后 SELECT 及发送失败时，从尾清除所有 chunk 引用并请求 GC；避免清理中途断电留下引用空洞。
- `SafeShareable.list` 两个重载现在返回 `SafeItemIteratorShareable`，提供 `getCount()`、`getMaxMetadataLength()` 和 `next()`。耗尽返回 null；只用于当前操作，不支持遍历中修改 Safe 或跨复位继续。
- `SafeSessionItemIterator` 预扫描匹配数和最大 `index + key + alias` 字节长度；`next()` 从当前位置继续扫描，累计扫描仍为两遍 O(N)。游标及私有 prefix 副本使用 `CLEAR_ON_RESET`；Safe 不持有传入 global 数组引用。每次 next 仍生成原有不可变 `SafeSessionItem` 包装对象，其数量与旧版相同，存储为持久对象。
- `SafeItemShareable` 增加 `getIndex/getKey/getAlias(byte[] dest, short offset)` 重载，返回实际长度；可选字段缺失返回 -1，存在但为空返回 0。原无参读取方法继续供其他命令使用。所有新导出方法沿用 `session.assertAccess()`。
- `CommandList` 根据最大单条元数据长度分配一次 global 缓冲。各条目依次将 index、key、alias 放入连续区间，取得长度后按原字段顺序编码，再复用同一缓冲读取下一项；空列表不分配元数据缓冲。
- 显式 RAM 分配由512B响应块、最大单条元数据、游标和固定请求/前缀副本决定，不再随条数增长。持久响应及每条包装对象仍随结果量增长，最终需要 GC。
- 既有非负 short 响应总长度约32767B、Safe条目计数类型及持久存储容量仍是限制；本轮不扩展这些范围。大单条元数据不是本轮目标。

## 验证和交付边界

- Java 11，30项定向测试通过；完整 `gradlew check` 运行249项模拟器测试，0失败、0错误、0跳过。
- 新增7项测试：writer的512/513B存储类型、普通writer仍为RAM及复位后清理；Safe独立游标/输入隔离、最大元数据长度及buffer范围；40条16B key与9B alias的完整List/过滤/256B分包/取消重试；缺失与空字段不会串入前项内容。既有授权测试扩展到枚举及3个缓冲读取重载。
- Identity、Safe、Monoid三份CAP转换和验证通过；Prettier、Inplate assert和diff检查通过。
- 未访问或安装实体卡，尚无本版List的实卡时间、RAM峰值或容量测量。模拟器的SIO上下文适配不模拟完整防火墙；global数组只作为调用参数/局部值，Safe私有prefix明确复制。
- Safe SIO接口变化，后续部署需要匹配的Safe与Monoid；不能只重装Monoid去调用旧Safe。升级Safe前仍需保留用户数据；Identity无需因本轮改动重装。
