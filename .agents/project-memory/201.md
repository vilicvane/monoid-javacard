# 双向实例绑定与 Bundle 的 Access 同步（2026-10-28）

[user] 批准双向绑定：Bundle 内同步只要求 Access PIN，非 Bundle 仍要求 Secret PIN，保留禁止自导入；遵循原有结构与风格并完成实卡验证。

[agent] 保留 Identity 向 Monoid 提供的、按调用方完整 AID 派生的稳定 token；Safe 继续在每次操作前核对它。新增相反方向的 Monoid 安装随机 token：32B 私有持久数组，只在真实 Secret PIN 认证成功后，将 SHA-256 摘要交给 Identity 绑定。

## 接口和权限

- IdentityShareable 新增 `bindMonoid(byte[] tokenHash)`。固定 Monoid AID、Identity 自己的 Secret 授权和无进行中的通信操作必须同时满足；同一摘要重复绑定不重新分配或写入。
- `encryptData` / `decryptData` 首参新增 `byte[] token`，不增加兼容重载。null 保持 Secret 授权路径；非 null 必须是已绑定 Monoid 实例的私有 token，并且仅允许 Bundle 密文02。
- Monoid 的 Export36 / Import37 请求响应不变，允许 Access 认证。Safe 在发送安装 token 前先核对 Identity；Command 当前为 Secret 时传 null，Access 时传安装 token。不能因 Identity 内残留的 Secret 授权而把 Access 调用降级到非 Bundle 路径。
- Identity 解密在同一次操作读取并消费封装版本后检查 Bundle-only 模式，避免单独预读版本再执行解密。无 Bundle 的 Access 传输拒绝6985；已有 Bundle 的 Access 导入01拒绝6982。
- Bundle 管理、PIN 更新、卡别名等原有 Secret 权限不变。客户端授权接口没有增加通用导出能力。

## 生命周期与边界

- Monoid 重装生成新 token；旧 Identity 的绑定不会自动认领它。必须再次验证 Secret PIN 才能重绑。只得到同一个 AID 对应的 Identity token 不足以逆推出新绑定所需的 Monoid token。
- Identity 替换仍被原有 forward binding 拒绝；不向不匹配的 Identity 发送 Monoid 私有 token。
- Reset 在既有事务中清除 Identity 的反向绑定、更新 pinned Identity token，并发布预先生成的 Monoid 新 token；Card ID、Authority 等原有保留规则不变。
- Bundle root、按调用方 AID／发送方公钥派生的密钥、条目密文格式全部不变。接收方公钥等于密文发送方时仍拒绝；A 导出、B 导入再导出、A 导入仍是允许的双成员恢复路径。
- 本功能绑定经过 Secret 授权的实例，不是代码签名或远程证明。新鲜导出的恢复链需要源卡 Access PIN，以及另一个成员上的 Secret PIN和替换代码所需的 GP 权限；已有密文不要求源卡再次在场。
