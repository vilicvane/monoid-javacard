# Monoid-001 Ed25519

[user] 要求将 Ed25519 加入 Monoid-001。

[agent] 沿用现有 seed/context 派生和 ViewKey/Sign 命令：

- `derivation: { type: 'monoid-001', curve: 'ed25519', context }` 派生 Ed25519。
- `curve` 省略或显式 `secp256r1` 选择原 P-256 分支，现有派生结果不变。
- Ed25519 ViewKey 返回 32B 公钥，没有 chainCode；Sign 使用 `cipher: 'ed25519'` 和原始 `message`，返回 64B 签名。
- 两个分支都拒绝 path/taproot；仍要求 64B seed，不支持对独立私钥条目继续派生。
- Set/List Applet Grant 的 Key 描述符保存并返回 curve。既有 Shareable 公钥/摘要签名方法继续固定 P-256，本轮不扩展 SIO。

## 派生与缓存

master 仍是 `HMAC-SHA512('Monoid-001', seed)`。P-256 的 HKDF info 保持
`label || 00 || context || retry`；Ed25519 使用
`label || 01 || context || 00`，取 HKDF-Expand-SHA512 的前 32B。
HKDF 的首块计数 01 另附在 info 后。固定位置的域字节隔离两条曲线，即使 context
可以任意取值，也不能构造相同的 HKDF 输入。

Ed25519 结果是私钥 seed，全零或全 FF 都是合法输入，不做 P-256 标量拒绝采样；
现有 CurveED25519 负责 SHA-512 展开与 clamping。Monoid001Derivation 的域在实例
创建时确定，Keystore 为两条曲线各复用一个实例，沿用 KeyDerivation 的 owner/source/input
缓存键及全局 32 项上限。Ed25519 公钥读取和签名复用既有 expandedKey 缓存。

[user] 要求明确分开 Ed25519 的一次派生与 P-256 的拒绝采样，复用公共部分。
[agent] Ed25519 在独立分支以 counter=0 调用一次 expand；P-256 循环重试并检查
标量范围。两者共享同一个 HKDF 首块展开方法及 workspace，编码与输出不变。
拆分后 26 项派生/签名测试与五 CAP 转换验证通过，格式和 diff 检查通过。

## 验证

独立 Node `crypto.hkdfSync` / Ed25519 生成固定公钥和签名向量，Java 另用 JCE HMAC
核对派生值。测试覆盖原 P-256 向量不变、空/二进制 context、原生/软件 HMAC、
两曲线交替与缓存淘汰、Ed25519 全零/全 FF seed 无拒绝采样、600B 消息跨 37B/255B
APDU 分片、字段重排、复位认证、seed 更新/删除以及非法 curve/path/cipher/taproot。

本轮仅进行本地验证，未操作实体卡或部署。
