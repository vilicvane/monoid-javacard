# Identity token 三次读取调用方 AID — 2026-10-20

## 需求与实现

- [user] 在移除每次校验的持久副本之后，要求将 AID 三次加入 token hash；随后要求实卡测性能，通过后提交推送。
- [agent] token 公式改为 `HMAC-SHA256(identitySecret, "Monoid Identity Token" || callerAID || callerAID || callerAID)`。每轮独立调用 `JCSystem.getPreviousContextAID().getBytes(...)`，立即把本轮完整 AID 加入 HMAC，不把首次快照简单复用三遍。
- `TOKEN_AID_ROUNDS` 为3，复用原有16B私有 caller 数组和 HMAC 工作区；最后一次 AID 快照交给缓存条目。不新增缓冲、公开接口或 APDU 字段。
- 仅缓存未命中时执行新增输入步骤。保留32槽持久 FIFO、缓存命中的三轮完整 AID 校验、Safe 最终 token 三轮比较和首次持久绑定；PIN 路径不变。
- 新公式取代148/150中的单次 AID 公式，token 值因此改变。旧绑定不自动重绑，也不增加旧公式兼容分支。本轮仅使用临时 AID，没有重装正式应用。

## 验证与边界

- `check buildJavaCard` 通过：329项 JUnit，零失败、错误、跳过；两正式 CAP 均转换零错误/警告且验证通过。
- 新增独立 JCE HMAC 对照，覆盖5B、8B、当前9B及16B调用方 AID，核对首次计算与缓存命中，并确认不同于旧单次 AID 公式。
- 新增运行时读取计数测试：冷请求在准入检查读取一次之后，HMAC输入再次独立读取三次，共四次。
- 首轮测试的16B AID fixture误写成17B，修正测试数据后通过；不是生产算法失败。保留初次失败日志。
- 全仓Prettier、Inplate、diff及5项JS测试通过；生产源码测试之后保持不变。此前151的实卡数值属于单次 AID 公式版本，本次按下述新冻结版本重新对照。
- 这是 HMAC 输入构造中的冗余读取，不替代缓存选择与最终相等性检查；模拟器对照和读取计数不证明物理故障注入抵抗能力。
- 本轮日志位于忽略目录 `.research/identity-token-aid-20261020/`：`validation.log` 为最终成功，`validation-initial.log` 为初次测试 fixture 失败。前轮151冻结研究输入保持原样，不为本轮生产修改更新历史 manifest。

- 从当前完整源码生成两版，唯一生产差异为 `TOKEN_AID_ROUNDS = 1` 与 `3`，双方都有32槽缓存、global直接比较及AID隔离。基线用于量出新增两轮的差分，并非逐字复现151的旧输入调用布局。
- 785个输入冻结并核对哈希；timing/peak/token各两版、共12个隔离CAP均转换零错误/警告且验证通过。timing仅重命名包和AID，peak/token剥离探针后精确还原timing源码。
- 每版108次真实业务计时、31次内存流程、16次独立token请求，共310/310通过。两版业务请求/响应字节数与分片一致；所有导出记录、两个host成员入组包独立解密，并通过导出验证实际导入Bundle密钥。不是三张实卡互刷。

## 时间与内存

单位ms，中位数；业务通常预热1次后5样本，reset Hello为3次独立PC/SC复位后采样。业务耗时为完整请求的PC/SC transmit之和，包含分片/GET RESPONSE，不含host密码学、日志、SELECT、复位或准备。

| 场景                   | AID一次 | AID三次 |
| ---------------------- | ------: | ------: |
| token重算，复用引擎    |  144.28 |  147.57 |
| token缓存命中          |   77.48 |   77.46 |
| token复位后命中        |   77.44 |   77.44 |
| Hello                  |  266.44 |  266.50 |
| Bundle Hello           |  289.81 |  289.77 |
| 三成员Create Bundle    | 2485.90 | 2489.19 |
| System Information对照 |  344.48 |  344.37 |

- 独立token探针在Monoid常规初始化前调用Identity；miss请求先开启调用方事务，使生产getToken跳过缓存发布，完成后commit。先单列首次懒初始化，再预热1次、测5次miss。随后普通无事务请求发布缓存，测5次hit和3次分别复位后的hit；全部返回token相同，不读取Identity secret。
- miss中位增加3.2898ms（2.28%），两版区间144.2489–144.3561与147.4804–148.9857ms不重叠；hit/复位hit区间重叠。这里是包含SIO、事务、分配、复制和GC的完整探针APDU，差分反映新增工作，不能把144/147ms称为孤立HMAC耗时。
- 16项真实业务计时前后区间全部重叠，中位变化绝对值均小于0.45%，本次未观察到明显业务性能退化。首次Hello单样本418.50→425.63ms、token首次懒初始化178.90→180.94ms包含资源初始化，不能代替稳定差分。
- 所有17项最低采样RAM及空闲读数一致。初始RESET1942B/DESELECT1936B，完整流程后1417/1408B；最紧为Create Bundle RESET373B/DESELECT368B，Import Bundle RESET465B。RESET/DESELECT重叠，不相加；采样不是连续原生峰值，持久32767饱和不代表真实剩余容量。
- 插桩确认双方只有首次Hello发生HMAC与缓存发布，之后及复位后命中缓存。本轮仅一个调用方占第一个槽，不代表满32槽性能；顺序安装、单卡测试，也不代表物理断电或故障注入验证。
