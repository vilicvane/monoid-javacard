# Current Monoid physical integration — 2026-10-12

Scope: working tree based on `42eda62`, with approved transient multipart request
assembly, Message slices and dispose/writer cleanup. The ACS ACR1552 card reported
ATR `3b8a800150564a434f503453494471`, T=1, IC type D321, batch 4839. Isolated 7D
Safe / 7E Monoid packages used public fixtures; production applet data was not
accessed. The uninstrumented Monoid CAP SHA-256 was
`197f2b74761e35b7c842ffe33fd35fde5bb18f950a174b225fb4ffa4f8734ec6`.

- Three seed-derived 150-byte Solana transfer signatures passed in 2.634–2.660 s;
  stored master took 2.507 s. Times cover the complete Sign APDU request,
  derivation and signing, excluding authentication/fixture creation and later
  probes. They do not measure the primitive alone.
- 512-byte Message first/last in CBOR passed in 2.905–2.915 s, three fragments.
  Seed/master public keys, chain codes and signatures matched independent Node
  HMAC/OpenSSL for `m/44'/501'/0'/0'`.
- BTC at `m/44'/0'/0'/0/0` passed twice in 1.179–1.183 s, followed each time by
  correct Solana signing without client-side context preparation.
- 1167-byte Message failed with default 255-byte fragments. Diagnostic-only
  persistent counters and SystemException output confirmed reason 2
  (NO_TRANSIENT_SPACE): the complete 1263-byte request expands 1024→1280 in the
  last APDU, leaving 16 B after reception and 0 B at the exception, before the
  EdDSA branch. Replaced arrays survive until the APDU boundary. A control using
  192-byte fragments expands in an intermediate APDU and signs correctly.
- 600-byte Create likewise failed with reason 2 at 255-byte fragmentation:
  1040 B after reception and 416 B at the exception. The 192-byte control passed.
  Do not treat that fragment size as a universal fix or capacity guarantee.
- Uninstrumented request replacement, GET RESPONSE protection, three-part GET
  of the 600-byte fixture, abandoned-response signing, and reset/re-authenticated
  signing passed. Idle transient RAM was 2320 B after short signing and 1968 B
  after a large response and later signing; writer capacity is retained.
  These are idle samples, not complete signing peaks. Reset/deselect memory
  readings overlap and must not be added together.

The complete integration is not ready for unrestricted long messages. Two known
limits remain: old/new receive buffers can coexist in the execution APDU, and
response capacity remains allocated after a large response. No source-level
memory-policy or protocol fix was made in this test. The 8192-byte ceiling is
only a protocol limit, not a guarantee of real-card RAM fit.
