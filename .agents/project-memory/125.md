# List流式响应与分批枚举

## 已批准方案

[user] 批准记录124实卡对照后的writer/分批读取方案，明确保留现有Safe枚举接口。

[agent] 内部增加`CBORResponse.writeNext(CBORWriter)`和`reset()`；一次回调完整编码一个单元，返回是否还有后续单元，false仍可写入最后一个单元。`CBORApduWriter.start(response, maxUnitLength)`为本次响应准备`256 + maxUnitLength`的RAM窗口。List通过现有方法写map/items/定长array头部，再每次回调调用一次原有`next()`并编码一条完整记录。

- 仅在待发字节少于256B时继续生成，每个APDU最多4次回调。记录跨包时保留已编码的尾部字节，不保留item wrapper。总响应不需要持久副本或累计short偏移。
- `hasPending`同时包含尚未发送的字节和未结束的来源。来源未结束时返回6100；结束后按窗口中已知剩余字节给出61xx，最终9000。短包也可能带61xx，客户端不能按数据包长度判断完成。
- 逐包请求GC；完成、取消、新命令、SELECT/deselect/reset及错误统一释放响应来源/iterator/窗口。初次生成失败沿用原错误CBOR；已发送部分响应后续生成失败应返回终止错误SW，不能把错误CBOR追加到原响应后以9000结束。
- 不改变Safe.list/iterator/SafeItemShareable的接口及对象稳定语义。仍遵循现有枚举期间不修改Safe的约定；跨逻辑通道的其他调用方不应并发修改Safe。
- 单条元数据使用当前APDU global缓冲读取，必要时使用局部global缓冲，不能跨APDU保存global数组。保留单条数据较小的场景，不借此扩展假设性大字段支持。
- 窗口整理延后到下一条APDU，发送后不再改写发送缓冲；兼容原来没有Le的初次请求。原有非流式响应仍使用按需chunk存储。

## 本地验证

[agent] 267项模拟器测试全部通过，无失败或跳过；三个正式CAP转换与验证、Prettier、Inplate检查通过。新增覆盖逐APDU4次回调、末次回调带数据并返回false、跨包单元、短Le、超过32KB总响应、取消/复位/错误清理，以及List长metadata和超过8KB响应。旧List测试改为按61xx读取至9000，不再假设每包恰好256B或固定两包。

## 实卡验证

[agent] 卡55690320、ACS ACR1552、T=1。隔离Identity/Safe/Monoid/filler使用B1/B2/B3/B4；生产List/writer未经插桩，Monoid只增加独立的空闲内存诊断命令，且仅在完整响应之前/之后调用。原有应用和PIN不参与测试。

120条测试记录均为10B index、16B key、9B alias、1B非secret data，前8条共享查询前缀。完整List为7569B，30包；8条过滤响应为512B，2包。所有成功结果均逐项检查index、key、alias、secret，并与host独立编码的CBOR逐字节比较。完整响应SHA256为`730cb86c543f2620064f52e1d03c5f7fcc231a737a252f957366df4a64c6d86e`。

- 耗时为本轮各档单次完整操作，包含卡片处理与PC/SC传输、逐包GC，不是算法计时或统计中位数。原记录123/124包含不同诊断插桩，不能直接据此声称性能提升。
- 全部档位的List前后持久余量一致；RESET/DESELECT余量也保持2120/2112B。这是完整响应边界的读数，不是命令内峰值。本样例的RAM窗口按代码计算为340B，与总条数无关。
- 2080B时旧版完整List只能处理26项，1056B时只能处理12项（记录124）；此次相同格式的120项均可完整读出。响应持久副本和单条APDU中不断积累wrapper这两项限制已去除。
- 正常空间、16416B和2080B均验证：错误CLA/P1的GET RESPONSE保留进度；新Hello命令和重新SELECT取消旧响应；重新认证后List、已知index的Get正常。取消后GET RESPONSE返回6985。
- 544B时已知index的普通Get也返回INTERNAL；本轮未进一步插桩定位具体分配点。不能把失败归因于响应总长度，也不保证零空间或未初始化客户端在满卡时仍能工作。错误响应以9000携带CBOR error，客户端仍须检查error。
- 释放filler后持久空间恢复42664B，120项完整List和已知index的Get再次成功；失败期间卡片未失联，没有删除测试数据来恢复读取。
- 生产数据包实际包含256/253/252B等长度，61xx续传正确；分包边界不必等于记录边界。模拟器额外验证短Le和更长总响应，未将这些模拟边界冒充实卡容量保证。
