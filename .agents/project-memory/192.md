# Authority URL 与可选的 OTP 可信时间

[user] Authority 可能由用户自行部署，APP 初始化时应允许选择或输入服务 URL，获取公钥后一并安装进 Identity。批准 Hello 只返回 URL（未配置时 false），不增加 Authority 公钥响应。批准 OTP 在未配置 Authority 时使用 APP 提供的时间，并更新相关文档。

[agent] 当前实现：

- Identity 安装数据为 `flags || [id4] || [authorityPublicKey65 || authorityUrlUTF8]`；bit0 控制 Card ID，bit1 控制完整 Authority 配置，URL 占剩余字节、不能为空。不接受旧的 key-only 配置。空参数及 flags=0 仍随机 ID、无 Authority；flags=1 仍可只恢复 ID。
- `IdentityShareable.getAuthority()` 返回调用期 global URL 副本或 null，沿用调用方检查。公钥保留在 Identity 内。URL/公钥与 Card ID 都作为安装配置，在 Reset 后保留；无运行时 setter。
- Monoid Hello 增加 `authority: string | false`，Safe 委托到验证了 token 的 Identity。Hello 无需 PIN，长 URL 可以使用现有响应分段。
- `build-install.ps1` 新增 `-AuthorityUrl`，与 `-AuthorityPublicKey` 成对输入，构建及 GP 前校验；脚本不获取网络公钥。正式9B实例 AID 与三个长度字段下，应用参数上限243B，URL上限为无 ID 时177B、有 ID 时173B，按 UTF-8 字节计。安装代码将 byte 长度按 unsigned 解析。
- OTP Prepare 接受两种互斥输入：`{data:41B, signature:64B, indices}` 或 `{time:8B, indices}`，time 为 unsigned big-endian Unix seconds。只有未配置 Authority 的 Identity 允许 raw time；可以直接 Prepare，不需要 Challenge。配置了 Authority 必须走原 challenge/签名路径，验签失败或服务不可用不会降级。
- 仍为每账户3窗口、1–16账户、Prepare 后经 Monoid Access（或 Secret）认证单 AID，再由 Calculate 消费一次许可。错误尝试丢弃旧 batch，解析完成后撤销旧授权再准备新 batch；畸形请求不会让后续有效 Prepare 复用旧许可。保留先前无持久时间水位、无每次上电总配额的语义。无 Authority 时不保证时间真实性，APP 可选择过去或未来时间。
