# Bundle 导入直接读取 global 数组

## 约定与实现

- [user] 在讨论 Reader 默认 global 与显式方法的区别后，批准显式增加 `bytesGlobal()`、`bytesGlobal(short expectedLength)`，Bundle 导入改用这两个入口，并删除 Safe 中的再次复制。
- [agent] `CBORReader` 共用原有 byte-string 解码，只按明确的参数选择 global 或原有 `CLEAR_ON_DESELECT` 分配。默认 `bytes()`、定长 `bytes(short)` 和 `text()` 不变，类型/长度检查及游标行为不变；没有新增 `textGlobal` 或调整 APDU/SIO 格式。
- `CommandImportBundle` 将发送者公钥和入组包直接读入 global 数组。`Safe.importBundle` 保留授权检查，直接传给 Identity，并用方法注释说明两个输入必须为 global。
- 源码检查确认 `Safe.importBundle` 只有该命令一个调用点。Identity 在本次解密调用内读取输入，没有把这两个 global 引用保存到字段或数组。global 引用限制是 Java Card 的运行时规定；模拟器不完整模拟防火墙，实卡验证单独记录。
- 三成员入组包为 `3 + 3 × 65 + 113 = 311B`，另有 65B 发送者公钥，中间副本载荷合计 376B。原 403B 请求仍占两个 256B 接收块；只消除解码与跨 Applet 之间的重复数组，不调整传输 RAM 阈值、共享 AES-GCM、16B 输出块或私有数组持久化。

## 验证

- 新增两项 Reader 测试，覆盖不定预期长度/指定长度/空 byte-string、后续 map 字段、输入不变、长度不匹配、截断及错误类型。
- 完整 312 项测试、39 个 suite，零失败/错误/跳过；两个正式 CAP 转换零错误/警告且 Verifier 通过。
- 代码独立审查通过；默认分配与原有游标语义保持。模拟器验证编码及业务流程，不将其作为 global 防火墙的证明。
- 实卡预检确认 APP 测试卡 CPLC `51433520`，仅系统应用，E0/E2 临时 AID 空闲。下述验证仅安装临时包，没有正式部署。

## 实卡对照

- 同卡 ACS ACR1552 PICC、T=1，使用一个实卡 Identity 和两个独立 host 密码学成员组成三成员名单；不是三张实体卡互刷。
- baseline 为本轮修改前的完整工作树，candidate 为上述三份生产文件修改；两版均包含共享 AES-GCM、16B 输出缓冲及私有数组持久化。性能与内存各构建独立 CAP 对，共八个 CAP，均转换零错误/警告且通过 Verifier。
- 608 个源码、配置及测试输入冻结哈希；插桩源码剥离探针后与对应生产快照完全相同，检查点调用两版一致。运行前保存每组安装 ledger，核对 mode/variant、卡号、CAP/manifest 哈希，避免误用报告标签。
- 四组各 40/40 次完整命令通过，共 160 次。正常入组在每次测量前 ResetBundle；正常及幂等各一次预热、三次正式测量。两版均通过正常/重复入组、不同密钥拒绝、已入组/空状态 tag 篡改拒绝及恢复、SELECT 后鉴权失效、ResetBundle 后恢复非对称导出。独立 host 解密导出条目确认实际 Bundle key，而不只是比较响应 hash。
- 时间取未插桩版各次 PC/SC transmit 之和，包含两个请求分片及 GET RESPONSE，排除 host 编码/密码运算、SELECT、ResetBundle 和准备步骤。按 baseline→candidate 顺序安装，未随机化或交错；三样本结论限定本次观察。

### RAM

两组插桩采用相同的持久探针数组，不额外分配 transient 缓冲。以下为正常/幂等各四轮（含预热）一致的 RESET/DESELECT 可用字节数：

| 检查点               |    baseline |   candidate |
| -------------------- | ----------: | ----------: |
| 请求接收完成         | 1128 / 1120 | 1128 / 1120 |
| sender 字段读取完成  | 1064 / 1056 | 1063 / 1056 |
| 两个字段读取完成     |   760 / 752 |   752 / 752 |
| Identity import 入口 |   384 / 384 |   752 / 752 |
| 本次操作采样最低值   |   352 / 352 |   720 / 720 |

- 最低余量增加 **368B**；冲突、两种 tag 拒绝和拒绝后成功恢复也均为 352→720B。未授权请求在解码前拒绝，保持 1128B。global 与普通 transient 的查询计量在解析点略有差异，不能把移除副本的 376B 载荷直接称为精确净收益。
- 请求接收检查点不变，Identity 入口不再出现第二次复制的下降，与代码改动一致。sender、字段、接收及 Identity 入口等关键点均有实值，不以“读取八页成功”代替采样有效性；原始探针页与汇总独立核对。
- 四组结束时查询的空闲 RAM 都为 RESET1640B/DESELECT1632B，改变的是操作过程余量。两个池不能相加；这些是检查点的可分配内存读数，不是连续原生峰值，也不保证所有操作顺序或更低 RAM 卡片可用。persistent32767 为饱和值。
- 实卡确认 global 引用能沿现有调用链通过防火墙，没有保存到字段造成异常。本轮验证 SELECT 与 ResetBundle，未声称真实掉电复位、满卡或耐久测试。
- 每组后删除 E2/E0 实例及包，最后 registry 与原始 baseline 一致，PC/SC 已释放；正式 AID 未安装。没有提交、暂存或推送。
